# B2 本地选择器 v3

按照 [B2建议](../../docs/dev/B2建议.md) 实现的独立仓颉选择器，读取老乡鸡 SQLite；业务服务也已接入 v3 选择器，工作台页面可切回实验 v1 对照。默认仅监听 `127.0.0.1:8091`，不修改数据库、不创建正式推荐。

## 启动

准备项目 SDK 与依赖后，在仓库根目录运行：

```sh
export JUXIAOBAO_CANGJIE_SDK=/你的SDK目录/cangjie
bash scripts/algorithm-dev.sh
```

浏览器打开 `http://127.0.0.1:8091`。远程环境需转发 8091 端口。当前 Sandbox 已有构建缓存，可运行：

```sh
JUXIAOBAO_CANGJIE_SDK=/tmp/juxiaobao-sdk/cangjie \
  JUXIAOBAO_DEV_SKIP_BUILD=true bash scripts/algorithm-dev.sh
```

`JUXIAOBAO_DEV_SKIP_BUILD=true` 跳过全工程依赖构建，仍编译最新独立 agent 与 dev server。`--build-only` 只编译。可配置 `JUXIAOBAO_DEV_PORT`、`JUXIAOBAO_DEV_DB` 和 `JUXIAOBAO_DEV_RESTAURANT`。

## 交互

- 输入用餐人数后，成员列表同步生成发起人、同行人 A、B、C……；增减成员也会反向同步人数。可为每位成员设置辣度、口味、忌口、过敏和饭量。
- 饭量小/正常/大/特别大对应 0.5/1/1.5/2 道热菜，总和向上取整。页面实时显示热菜需求，主食默认每人一份。
- 展开本店食材搜索、指定菜品、小吃/饮品愿望；小吃和饮品可同时选多种，每种明确选择 1–100 份；“能吃多辣”和“想吃多辣”分开设置。
- 本次主食可选默认米饭、明确不要、换面、指定其他主食。只显示菜单事实中已核对为一个单人单位的主食，不提供用户手工确认规格的覆盖入口；过敏规则照常生效。
- 其他要求文本只提供有限的主食解释提议，点击“确认应用”才改选项；“不想吃饭”保持待澄清，未识别文本不参与自动约束。
- 点击“5人 / 45元 / 重辣”预设可复现此前讨论场景。结果列出费用、菜品简介、热菜需求、个人份量分配、适配覆盖和未满足愿望。
- 菜单表支持 unknown/下架模拟、个人适配检查，输入/结果可导出再载入。修改输入后必须重跑才能导出。
- 保存默认值只保存第1位成员的常用字段到当前浏览器，不保存本局愿望或主食覆盖。尚未对接正式账号默认配置 API。

## 搜索与事实

`src/agent/meal.cj` 的 `buildMealRecommendation` 使用缓存适配矩阵、可行种子、保留不同费用档位的有限束搜索、剩余额度内最多三轮单项替换。以整数最大流分配热菜半份单位，避免某位成员只能分到自己不能吃的菜。

先满足硬预算、过敏、个人热菜及主食需求，再比较愿望、两种适配菜选择、蔬菜和预算档位；进入90%–100%档位后，优先压低单品最大份数及总加份数，再接近预算上限。自动推荐优先让同一道非主食菜少于人数（单人时优先最多1份）；若不同适配菜全部各取一份仍到不了预算档位，才均匀增加必要份数，不再集中堆叠一种小吃。成员明确填写的小吃/饮料数量始终按原数处理。热菜最多 2H 份、单道热菜最多2份、汤最多1份；设置预算时可自动加入适配的小吃/饮料，并在结果中明确提示；没有预算时仍只加入成员明确选择的额外项。主食按人自动补足，套餐内主食先抵扣。新实验输入用 `wantedExtras: [{dishId, quantity}]` 表达份数，仍兼容旧导出的 `wantedExtraIds`（每项按1份）。

这是有扩展上限和时限的启发式搜索，不保证全局最优。缺少预算内方案或主食事实时明确返回缺口。饭量是团队约定的点菜估算，不是卡路里或保证吃饱。

`scripts/prepare-meal-metadata.py` 从 SQLite 导入溯源和 `data/fixtures/meal-annotations.json` 生成绑定餐厅/菜单版本的角色事实。原数据中的辅食不再计入正餐热菜。主料标注只采用当前配方实际存在的食材；未核对的主料不能冒认愿望已满足。食材展示隐藏基础调味项，但完整配方继续参与适配。午餐肉肉种未明时对不吃猪肉者标为不确定。

84 道真实菜和图片均来自已导入 Excel。角色/主料补充事实存独立文件，不改原 SQLite；不补造营养或重量。2026-10-20 用户确认除中份、大份鸡汤外均为单人份，所有已核对主食据此按1个单人单位计，面条可自动选择；中份/大份鸡汤仍保留原表多人份资料。

## 验证

```sh
bash scripts/test-algorithm-dev.sh
```

运行 agent 单元测试和临时回环服务上的真实 SQLite/HTTP 测试，结束后关闭服务，并核对 SQLite 摘要未改变。测试需要本地 socket 权限。已有 server 编译后可单独执行 `python3 tests/algorithm-dev-smoke.py`。

工作台另有 SQLite/HTTP 回归与页面 JavaScript 语法检查；工作台界面尚未执行真实浏览器点击验证。消费者与商家正式应用的浏览器测试见根目录 README。

2026-10-20 本地验证：仓颉 agent 37/37、元数据测试 3/3、真实 SQLite/HTTP 场景 16/16 通过；其中单人蛋奶素¥100自动补充到预算档位、多份小吃/饮品、5人×45元混合限制等场景均通过，SQLite 摘要保持不变。

## Azure IP 直接访问

```sh
JUXIAOBAO_DEV_HOST=0.0.0.0 JUXIAOBAO_DEV_ORIGIN=http://20.48.96.44:8091 \
JUXIAOBAO_CANGJIE_SDK=/tmp/juxiaobao-sdk/cangjie JUXIAOBAO_DEV_SKIP_BUILD=true \
bash scripts/algorithm-dev.sh
```

Azure 网络安全组入站需允许 TCP 8091；访问 `http://20.48.96.44:8091/`，不需要域名或 SSH 隧道。换 IP/端口时同步修改 `JUXIAOBAO_DEV_ORIGIN`；服务仍拒绝其他网页发起的跨源推荐请求。
